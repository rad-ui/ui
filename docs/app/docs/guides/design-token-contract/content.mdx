# Design token contract

The `--rad-ui-*` custom properties that Clarity, the default theme, is built from. They exist once you import `@radui/ui/themes/default.css`; the headless components never read them. Override them to retheme Clarity, or read them from your own CSS so your parts and Rad UI's share one scale.

The source of truth is `styles/cssTokens/` in the repository; `styles/jsTokens/` mirrors the names for JavaScript, and `src/tokenGen/` generates both.

## Naming

Every public token starts with `--rad-ui-`, then a family and a name in kebab-case: `--rad-ui-color-gray-100`, `--rad-ui-radius-md`, `--rad-ui-spacing-4`.

## Families

| Family | Tokens | Notes |
| --- | --- | --- |
| Colour scales | `--rad-ui-color-<ramp>-<step>`, steps `50 100 200 300 400 500 600 700 800 900 950 1000` | 31 ramps: `gray`, `mauve`, `slate`, `sage`, `olive`, `sand`, `tomato`, `red`, `ruby`, `crimson`, `pink`, `plum`, `purple`, `violet`, `iris`, `indigo`, `blue`, `cyan`, `teal`, `jade`, `green`, `grass`, `brown`, `bronze`, `gold`, `sky`, `mint`, `lime`, `yellow`, `amber`, `orange`. A step is its distance from the page background, so the same step reads the same in light and dark. |
| Accent | `--rad-ui-color-accent-<step>` | The same 12 steps, pointed at whichever ramp `Theme accentColor` names. |
| Semantic colour | `--rad-ui-surface-canvas / -panel / -subtle / -muted / -hover / -inverse`, `--rad-ui-text-primary / -secondary / -muted / -strong / -inverse`, `--rad-ui-border-soft / -default / -strong` | What components read for backgrounds, text and borders. Override these to move every component at once. |
| Status | `--rad-ui-info-*`, `--rad-ui-success-*`, `--rad-ui-warning-*` | Callout, Badge and Field states. |
| Radius | `--rad-ui-radius-none / -sm / -md / -lg / -xl / -full`, `--rad-ui-control-radius-sm / -md / -lg / -pill` | `Theme radius` sets the control radii. |
| Spacing | `--rad-ui-spacing-0 1 2 3 4 5 6 8 10 12` | Padding and gaps. |
| Density | `--rad-ui-density-gap-xs … -xl`, `--rad-ui-component-font-size-dense / -comfortable` | `Theme scaling`. |
| Typography | `--rad-ui-font-size-1 … -5` (with `-1-5` and `-2-5` half steps), `--rad-ui-font-weight-regular / -medium / -semibold / -bold`, `--rad-ui-line-height-1 … -4` | |
| Elevation | `--rad-ui-shadow-none / -xs … -xl`, `--rad-ui-elevation-xs … -lg` (each a `-background`, `-border` and `-shadow`) | Popups and cards. |
| Focus | `--rad-ui-focus-ring-shadow` and its `-inset`, `-offset`, `-outset`, `-contained` variants, `--rad-ui-ring-strong` | Every `:focus-visible` ring. |
| Motion | `--rad-ui-motion-duration-instant / -fast / -normal / -slow / -slower / -reduced`, `--rad-ui-motion-easing-standard / -entrance / -exit / -emphasized / -spring / -linear`, `--rad-ui-transition-*` | Durations collapse to `-reduced` under `prefers-reduced-motion`. |
| Overlay | `--rad-ui-overlay-scrim`, `--rad-ui-overlay-width-sm / -md / -lg`, `--rad-ui-overlay-max-height-md`, `--rad-ui-overlay-viewport-gutter` | Dialog, Drawer, menus. |
| Stacking | `--rad-ui-z-index-base / -sticky / -dropdown / -overlay / -portal` | |
| Component | `--rad-ui-button-*`, `--rad-ui-badge-*`, `--rad-ui-dialog-*`, `--rad-ui-drawer-*`, `--rad-ui-table-*`, … | Per-component knobs that read the families above; listed on each component's Styles tab. |

`Theme` writes its settings to the container as `data-rad-ui-theme`, `data-rad-ui-accent-color`, `data-rad-ui-radius` and `data-rad-ui-scaling`, and the stylesheet selects token values by them. That is why a nested `Theme` can change accent or appearance for one section.

## Overriding

Override on top of the full theme, never instead of it:

```css
@import "@radui/ui/themes/default.css";

:root {
  --rad-ui-radius-md: 8px;
  --rad-ui-font-size-3: 0.9375rem;
}

[data-rad-ui-theme="dark"] {
  --rad-ui-surface-panel: #111;
}
```

Scope overrides to `:root`, a `Theme` container or any stable ancestor. Everything you don't override keeps the theme's value. Defining only a handful of tokens without importing the stylesheet is not a theme: component CSS reads every family, and a missing token leaves the declaration invalid rather than falling back to a Rad UI default.

The `var(--token, fallback)` branches you may see inside the theme CSS are implementation detail for migrations, not an API. Provide the tokens you depend on.

## Using tokens in your own CSS

Read them like any custom property, so your components follow the same appearance and accent switches as Rad UI's:

```css
.sidebar {
  background: var(--rad-ui-surface-subtle);
  border-right: 1px solid var(--rad-ui-border-soft);
  color: var(--rad-ui-text-primary);
  transition: background var(--rad-ui-motion-duration-fast) var(--rad-ui-motion-easing-standard);
}
```

The Tailwind preset exposes the colour ramps as utilities ([Usage](/docs/first-steps/usage#tailwind-preset)); the other families are CSS only.

## Changing the contract

Adding or renaming a token is a library change: update `styles/cssTokens/`, run `npm run generate-tokens`, mirror the name in `styles/jsTokens/` when Tailwind or JavaScript consumers need it, document it here, and check the Clarity components that read it. Removing or renaming a documented token is a breaking change.
