# Usage

How Rad UI fits into an app once it is installed: imports, `Theme`, class namespaces and the Tailwind preset. For the install itself and a first component, see [Installation](/docs/first-steps/installation); for Vite, Next.js and Remix specifics, [Framework usage](/docs/guides/framework-usage).

## Imports

Every component has its own entry point. Import the one you use:

```tsx
import Button from "@radui/ui/Button";
import Dialog from "@radui/ui/Dialog";
```

Compound components are objects of parts: `Dialog.Root`, `Dialog.Trigger`, `Dialog.Content`. In a React Server Component file use a namespace import instead (`import * as Dialog from "@radui/ui/Dialog"`); see [TypeScript](/docs/guides/typescript#server-components).

The root `@radui/ui` barrel exists for compatibility. Prefer the per-component paths in application code: they keep bundles small and make it obvious which components a file depends on ([Barrel export policy](/docs/contributing/barrel-export-policy)).

## Wrap components in your own

Most teams wrap Rad UI parts once and export the wrapper as their design system's API: the wrapper fixes the variants, styles and defaults, and the Rad UI part keeps the behaviour. [Design system integration](/docs/guides/design-system-integration) has recipes; [TypeScript](/docs/guides/typescript) shows how to type the wrapper.

## Styles are opt-in

Components render without any library CSS. You have three options, and they combine:

- **Bring your own.** Style the parts through `className` and their `data-*` state attributes with Tailwind, CSS Modules, SCSS or plain CSS. [Styling and customization](/docs/guides/styling-and-customization) lists the supported hooks.
- **Clarity, the default theme.** Import it once and turn on the generated class names it targets (next section).
- **The Tailwind preset.** Rad UI's colour scales as Tailwind utilities, with or without Clarity.

```tsx
import "@radui/ui/themes/default.css";
```

## Theme

`Theme` sets the visual context for everything inside it: appearance, accent colour, radius and scale. Nest it to change those for one section.

```tsx
import Theme from "@radui/ui/Theme";

const App = () => (
    <Theme appearance="dark" accentColor="blue">
        <YourApp />
    </Theme>
);
```

`Theme` exposes its settings on its container as `data-rad-ui-theme`, `data-rad-ui-accent-color`, `data-rad-ui-radius` and `data-rad-ui-scaling`, so your own CSS can key off them. The full prop list is on the [Theme](/docs/components/theme) page.

### `classNamespace`

By default `Theme` adds no class names to components; styling happens through `data-*` attributes. Pass `classNamespace` to get a stable class on every part:

```tsx
<Theme classNamespace="rad-ui">
    <Accordion.Root />   {/* renders class="rad-ui-accordion-root" */}
</Theme>
```

Clarity's selectors expect the `rad-ui` namespace, so the theme needs both the stylesheet and `classNamespace="rad-ui"`:

```tsx
import "@radui/ui/themes/default.css";
import Theme from "@radui/ui/Theme";

const App = () => (
    <Theme classNamespace="rad-ui" appearance="dark" accentColor="gray">
        <YourApp />
    </Theme>
);
```

With your own stylesheet, pick any namespace (`classNamespace="acme"` gives `acme-accordion-root`, `acme-accordion-item`, and so on). A single component can opt out of the namespace with `customRootClass`, which is how you restyle one component while the rest stays on Clarity.

## Tailwind preset

Import the preset after Tailwind in your global stylesheet:

```css
/* globals.css */
@import "tailwindcss";
@import "@radui/ui/themes/tailwind-presets/default.css";
```

It exposes every Rad UI colour ramp as utilities (`bg-gray-100`, `text-gray-1000`, `border-gray-300`, and the same for `blue`, `red`, `green`, …). Each value resolves through a `--rad-ui-*` custom property, so switching the theme or appearance re-resolves the utilities without a rebuild; opacity modifiers such as `bg-gray-500/90` work as usual.

### The numbers follow the theme, not light and dark

A colour's number is its distance from the page background, in both appearances. Low numbers sit close to the background, high numbers far from it, so one class reads correctly in light and dark mode:

| Class | Light theme | Dark theme |
| --- | --- | --- |
| `bg-red-100` | pale red tint | deep red tint |
| `text-red-900` | dark red | light red |

This differs from plain Tailwind, where `red-300` is always a light red. For text that must stand out, use a high number (`text-red-900`); for subtle fills, a low one (`bg-red-100`). Don't reach for `text-red-300` to get "light red on dark": in dark mode it is close to the background.

The preset covers colours only. Spacing, radius, shadow and typography utilities keep Tailwind's defaults.

### Utilities that lose to the theme

Clarity's CSS is not in a cascade layer and Tailwind v4's utilities are, so a utility such as `text-2xl` on a `Heading` loses to the theme's font size. Import the theme into a layer of its own to let utilities win; [Styling and customization](/docs/guides/styling-and-customization#overriding-the-default-theme-with-tailwind) shows the three lines.

### Tailwind v3

The v4 CSS preset replaced the JavaScript preset for Tailwind v3. Upgrade Tailwind before upgrading Rad UI; the v3 preset is gone.
