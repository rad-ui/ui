# Contributing to Rad UI

Bug fixes, new components, docs and accessibility reports are all welcome. The library is small enough that one well-made pull request changes it.

<StarUs />

## Pick something

- [Good first issues](https://github.com/rad-ui/ui/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22) are scoped for a first contribution.
- Comment on the issue before you start, so two people don't build the same fix. Ask questions there or on [Discord](https://discord.gg/nMaQfeEPNp).
- Read [Before you start](/docs/contributing/before-you-start) and [Setting up the dev environment](/docs/contributing/setting-up-dev-environment) once.

## Make the change

1. Branch from `main`: `yourname/fix-issue-123`.
2. Follow the [naming conventions](/docs/contributing/naming-conventions) for new files.
3. Add or update tests for behaviour you changed; keyboard paths and ARIA states count as behaviour ([snapshot policy](/docs/contributing/snapshot-testing-policy)).
4. Update the component's docs page and stories when a public API or a visible state changed.
5. Add a changeset if the change belongs in the release notes ([Changeset quality](/docs/contributing/changeset-quality)).
6. Run the [contributor checklist](/docs/contributing/contributor-checklist).

## Open the pull request

Target `main`. Say what changed and why, link the issue, and attach a screenshot or short video for anything visual. CI runs lint, tests, coverage, the docs build and Chromatic; a maintainer reviews and merges, and your change ships in the next release.
